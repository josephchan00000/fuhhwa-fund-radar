# 新聞報告：文風與格式

> 欄位標籤一律加粗體、速覽給「10 秒讀者」、卡片每句 ≤40 字與每欄粗體 2–3 處、正文不寫查證過程；各自的閘門。
> 原始資料：CLAUDE.md「指令：全部更新」步驟 2；程式：`arm/usnews.py` 的 `LABEL_RULE`、`BRIEF_STYLE`、`READ_RULE`、`HILITE_RULE`、`extract_cards()`；渲染 `arm/fund_dashboard.py` 的 `_lines()`；閘門：`scripts/check_reports.py`
> 最後更新：2026-10-29
> 第 5 段瘦身之前 CLAUDE.md 仍是正本：那幾段改了，這一頁也要跟著改（`python3 scripts/wiki_facts.py` 會檢查）。

上層：[新聞報告規則](news-rules.md)（哪條規則在哪支程式、派工要點名什麼、生效條件）。卡片在儀表板怎麼解析、排序，見 [新聞卡](../main/news-cards.md)。

## 現在怎麼運作

### 卡內欄位標籤一律加粗體（`usnews.LABEL_RULE`）

- 寫法：`N. **新聞摘要**：…`、`N. **漲跌分析**：…`，其他欄位標籤也一樣加粗。
- 原因：儀表板 `arm/usnews.extract_cards()` 抽摘要／影響分析的 regex **要求標籤帶 `**`**（`^\s*\d*\.?\s*\*\*新聞摘要\*\*[：:]`）。
  子代理寫成 `1. 新聞摘要：`（無粗體）→ 解析全落空、`summary`/`points` 皆空 → **儀表板該卡只剩參考連結、詳細分析整片消失**。
- 閘門：`check_reports.py` 的「摘要／影響分析皆空」檢查（[全部更新](daily-update.md) 步驟 3），🔴 訊息會直接指出標籤沒加粗體。
  但**源頭仍是派工時要講清楚**。

### 速覽／總覽段＝「10 秒讀者」（`usnews.BRIEF_STYLE`）

五份版型自動帶入，改規則改那支常數即可。六條：

1. 整段 ≤220 字、≤3 小段、每句 ≤35 字。
2. 結論先行：第一句就是方向＋牽動誰，數字擺第二句以後。
3. **版型與內規標籤不得入正文**（「國際背景一句帶過」「（細節留給總經與美股報告）」「盤前研判（中性陳述）」——要分段就直接換段，
   同「查證過程不入正文」原則）。
4. 刪填充語（值得注意的是／整體而言／換言之／這也是…的背景）。
5. **粗體每小段 2–3 處、結論詞組也要標**（方向與受影響對象、關鍵事件名、檢核點），不是只標數字——原本整段只有數字有底色，讀者沒有落點。
6. 形容詞能換成數字或具體事實就換（寫「跌破五日線」不寫「表現不佳」）。

**卡片求深、速覽求快**，與 `depth_note` 的深度六條不衝突（見 [深度與漲跌分析](news-rules-depth.md)）。

閘門 `check_reports.py` 的 `_check_brief`（2026-09-01 起）：散文超 320 字／出現版型標籤與填充語／粗體 <2 處 → 🔴。
**字數只算散文段、條列另計**：條列以條數 ≤6、每條 ≤130 字設限，免得有人把長文塞進 bullet 繞過上限。

### 卡片可讀性（`usnews.READ_RULE`）

與深度六條**並行不衝突**——深度講「要寫到幾層因果」，這條講「同樣的內容要寫成讀得下去的樣子」，總字數不減。五條：

1. **每句 ≤40 字**。
2. **每欄 2–3 處粗體、結論詞組也要標**（`HILITE_RULE` 同樣是 2–3 處）。
3. **多層傳導分句寫**（「第一層是資金：…。第二層是…。」每層各自成句）；「後續觀察：…」獨立成句、置於欄末。
4. 刪填充語。
5. 形容詞能換數字就換。

- **渲染端配套 `fund_dashboard._lines()`**：欄內遇「第N層／其N／①」與句末「後續觀察：」自動斷行（後者另加虛線分隔、壓低對比）。
  **只認明確列舉標記、句號一律不亂斷**——亂斷會把「甲公司。乙公司」這種連續敘述切碎，比不斷更難讀。純呈現層、不改字，既有報告重建即生效。
- 閘門 `check_reports._check_card_read`（**2026-09-02 起**，之前的報告不回溯）：每卡粗體 <3 處／超過 60 字的句子 >2 句／出現填充語 → 🔴。

### 正文不寫查證過程（`usnews.HILITE_RULE` 數據口徑段）

- 數字查不到（未達兩來源一致）→ 正文就自然地只寫方向與定性描述，像一般新聞一樣。
- 「未取得兩個獨立來源一致值」「本文一律不列數字」「依內規」「見資料侷限說明」這類流程性字句**只能寫在文末「資料侷限說明」段**，
  總覽／速覽／卡片各欄嚴禁出現、更不得加粗。
- 「資料來源機制說明」也是流程性字句：讀者不知道也不需要知道數字從哪支檔讀，**檔名／欄位名／「落檔」字樣一律不得入正文**。
- 閘門 `check_reports.py` 的 `_check_process_language()`（2026-08-17 起）：`_PROCESS_RE`＝落檔／series.*／*.json＋08-04 那批句式；
  「資料侷限」「合規」段豁免。

## 不能改的規則

- 派工 prompt 一定要寫明卡內欄位標籤「必須加粗體」`N. **新聞摘要**：…`。
- 標籤沒加粗體時改報告：把該報告的 `N. 標籤：` 改成 `N. **標籤**：`，不要改渲染端（原因見 [新聞卡](../main/news-cards.md)）。
- 粗體每欄不可再設「每欄至多 2 處」這種上限。
- 生效條件＝merge 進 main 後做一次「排程搬家」（同其他提示包規則，見 [新聞報告規則](news-rules.md)）。

## 踩過的坑

- **卡片詳細分析整片消失（2026-07-31 連三次）**：子代理寫成 `1. 新聞摘要：`（無粗體），解析全落空；合規掃描與舊版 check_reports 都照樣 🟢，
  因為連結與徽章都在，看起來一切正常。修法：`check_reports.py` 加「摘要／影響分析皆空」檢查；粗體要求寫進 `usnews.LABEL_RULE`。
  完整經過見 [新聞卡](../main/news-cards.md)。
- **免責文加粗放在速覽正文（2026-08-04）**：盤前速覽把整句免責文加粗放在正文，使用者直接開罵：「沒抓到數字就算了，還寫出來還加粗體是在幹嘛」。
  修法：寫進 `usnews.HILITE_RULE` 數據口徑段（正文禁「查證過程」字句）。
- **資料來源機制說明寫進正文（2026-08-17，同型再犯）**：昨夜美股總覽正文出現「費半與 ADR 數字取自本機官方落檔 `series.sox`／`series.tsm_adr`」。
  使用者：「請避免之後再發生」。修法：`check_reports.py` 的 `_check_process_language()` 結構性擋下。
  歷史報告掃描顯示「詳見資料侷限說明」在速覽正文其實反覆復發，此閘門一併根治。
- **速覽閘門首版把散文和條列合計字數（2026-09-01）**：美股與總經那種「指數收盤條列＋一段解析」的索引式總覽必紅——條列本來就好掃、
  不是使用者抱怨的長篇敘述。修法：字數只算散文段，條列改以條數與每條字數設限。
- **粗體上限讓卡片沒有落點（2026-09-01）**：`HILITE_RULE` 原本寫「每欄至多 2 處」——那個上限正是台股卡只有 0–3 處、
  其中一張深度卡整張沒粗體的來源；改為 2–3 處。
- **卡片句子太長（2026-09-01 實測）**：當日卡片均長 42–70 字、單句最長 146 字，一句塞三四個子句讀者中途就棄。修法：每句 ≤40 字。
