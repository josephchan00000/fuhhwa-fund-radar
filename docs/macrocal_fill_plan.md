# 總經行事曆「實際值沒更新」規劃（2026-10-30）

> 使用者 2026-10-30：「我剛剛看主頁的總經的行事曆有資料沒更新到，幫我詳細規劃解決」。
> 第 5 節的決定使用者已回覆（第 8 節）；一段一段做、每段做完給使用者看。

## 1. 現象

**今天（10/30）的行事曆有 6 列日期已經過了，狀態還是「未公布」：**

| 日期 | 項目 | 實際上 |
|---|---|---|
| 10/26–29 | 中：二十屆五中全會 | 會已開完 |
| 10/28 | 台：9月景氣對策信號（16:00） | **已公布：41 分、紅燈。CI 10/30 01:31 已從國發會抓進專案（景氣頁在用），行事曆沒用上** |

**還有兩種平常看不出來的：**

1. **當天公布的要等到隔天早上**：行事曆一天只在 06:35 更新一次。台灣數據 16:00、歐洲傍晚、美國晚上 20:30 公布的，當天整天都顯示「未公布」。
2. **週五公布的永遠不會出現實際值**：週六的行事曆換成下一週。10/17、10/24 兩份週末版都沒有上週五的列，所以週五的非農、日本 CPI、美國 PMI 等結果，網頁上從沒出現過。

**多常發生**：7/1 以來的 117 份行事曆裡，有 11 份出現「日期已過但沒填」的列（共 19 列）；這週變多：10/27 1 列、10/28 1 列、10/29 3 列、10/30 6 列。

## 2. 原因

| | 原因 | 說明 |
|---|---|---|
| R1 | 一天只更新一次 | 實際值只靠 06:35 排程的 Claude 上網查證；其他時間沒有任何程式會更新行事曆 |
| R2 | 週末換成下週 | 週末版只寫下週（`macronews.target_week_start`），上週五的結果沒地方放 |
| R3 | 早上查證漏掉、沒人擋 | 要兩家來源一致才填；沒填也不會被任何檢查擋下（漂移閘門只擋「已公布退回未公布」） |
| R4 | 沒用專案裡已有的官方資料 | 景氣頁每天從國發會、主計總處、經濟部、美國勞工統計局、勞工部、紐約聯準銀行抓官方數字，行事曆沒有接過去（鐵則：說「沒有資料」之前先查專案裡有沒有人在抓） |
| R5 | 頁面分不出兩種「未公布」 | 「還沒到公布時間」和「已經公布、我們還沒補」都顯示「未公布」，沒有過期標記（鐵則：抓不到就沿用，一定要配過期標記） |

## 3. 目標

- 已過公布時間的列，**最晚隔天早上一定有實際值**；真的沒有就寫原因（延期、取消、官方沒有數字）。
- 有官方、程式抓得到的指標，**公布後幾小時內自動補上**，不必等隔天。
- **週末也看得到上週五的結果**。
- 還沒補上的，頁面標「**待更新**」，不再假裝「未公布」。

## 4. 做法（分四段，每段做完給你看）

### 第一段：頁面誠實標示＋週末保留上週結果

- 日期早於今天、狀態仍是未公布的列 → 狀態改顯示琥珀色「⚠ 待更新」（滑過說明「公布時間已過，實際值還沒補上」）；
  行事曆標題旁加「N 項待更新」；首頁「資料更新時間」區塊也列這一項（新增資料來源要兩處都加）。
- 週末版：提示包規則改成「週末版保留上週五的列，以及上週還沒補齊的列，並填上實際值」；
  頁面把這些列放在「上週結果」小表，不算進每週 30 列的上限。
- 列印版同步改。

### 第二段：官方自動補值（CI 做，不花 Claude）

新程式 `arm/calfill.py`：行事曆的列對到官方序列，**先只接專案已經在抓的**：

| 行事曆的列 | 官方來源（景氣頁已在抓） | 寫法 |
|---|---|---|
| 台：N月景氣對策信號 | 國發會（`ndc`） | 41分（紅燈） |
| 台：N月CPI（年增） | 主計總處（`twcpi`） | +2.73% |
| 台：N月外銷訂單（年增） | 經濟部（`orders`，同月去年算年增） | +x.x% |
| 美：FOMC 利率決議 | 紐約聯準銀行（`fedtgt`） | 維持3.75%–4.00% |
| 美：N月失業率 | 勞工統計局（`us_bls`） | 4.2% |
| 美：N月CPI（年增；核心） | 勞工統計局（未季調指數算年增） | +x.x%（核心+x.x%） |

- **CI 每一班都跑**（06 點、15:40、19:10、22:05、凌晨各班）：找出最近一份行事曆裡「日期已到、實際值空白」的列，有官方值就**直接寫進那份 `reports/macrocal/*.md`**：
  填實際值、狀態改已公布、「註」加一行「官方自動補值：9月景氣對策信號 41分（紅燈）——國發會，10/30 01:31 取得」，和當班資料一起 commit 進 main。
  隔天早上的 Claude 以昨天版當底稿，會自然沿用這些數字，網頁和列印版也只有一個來源。
- **規則（寧缺勿錯）**：只補空白的；月份或週別對不上、序列還沒更新就不補；
  Claude 已經填了而且和官方不同 → 不覆寫，寫進註與日誌，隔天早上依官方修正（「有官方數據一切以官方為準」）。
- **公布日重抓**：月資料現在「一天成功抓一次」，早上抓到舊月份就整天不再抓。改成：排程錨（`config/official_schedule.json`）上的公布日，公布時間之後再抓一次（例：國發會 16:00 公布 → 19:10 那班再抓）。

### 第三段：擴充官方來源（先用 CI 探針確認抓得到，才接上）

| 指標 | 來源 | 備註 |
|---|---|---|
| 非農、PPI、JOLTS 職缺、ECI、平均時薪 | 勞工統計局 API（已在用） | 一次可查 25 個序列 |
| 初領失業金（季調） | 勞工部 | 每週都有、最常出現的美國項目（近 7 週出現 7 次）；現在抓的是未季調 |
| 歐洲央行存款利率 | 歐洲央行資料 API | 公開、不用金鑰 |
| 台灣出口年增 | 財政部 | 國發會那份是景氣指標構成項目，不是新聞稿的數字 |
| 台灣 GDP 概估年增 | 主計總處 | `twgdp` 已有季資料，要確認算得出新聞稿的年增率 |
| 美國 GDP、PCE 物價 | BEA | **要免費金鑰**（你申請後放 GitHub secret）；不申請就留給早上的 Claude |

- FRED 不用：CI 連不上（景氣頁 2026-10-17 探針三輪都逾時）。
- 誠實的預期：近 7 週平均每週 21 列，官方能自動補的，第二段約 5%、第三段做完約 17%。
  **其餘約八成（財報、法說、日歐中數據、聯準會官員談話、民間調查如 ISM 與消費者信心）還是要靠 Claude 上網查證**，所以第四段一定要做。

### 第四段：早上的 Claude 必補＋檢查擋下

- 提示包多一段「**已過公布時間、實際值還空白**」清單（從昨日版算出來）：每一列都要填實際值（附來源），或在「註」寫原因（延期、取消、官方沒有數字）。
- `check_reports.py` 新檢查：今天的行事曆還有「日期早於今天、狀態未公布、註也沒提到」的列 → 🔴，要補完才能推。
- 生效：merge 進 main 後的下一班（排程會話每天 06:36 會先合併 main）。

## 6. 不做的事

- 不拿第三方彙整站的數字自動補，只用官方。
- 不把行事曆改成程式自己寫：事件清單、預期值、法說與財報仍由 Claude 查證。
- 不放寬每週 30 列的上限（「上週結果」另外算）。
