# 儀表板版面重新設計規劃書 — 「業務優先」資訊架構

> 目標：讓**投信內部業務**打開儀表板 3 秒內抓到今日重點、30 秒內找到可以對客戶／通路講的素材、3 分鐘內備齊單檔基金的完整說法。
> 範圍：`dashboard/index.html`（由 `arm/fund_dashboard.py` 產生）之資訊架構、視覺層級、互動邏輯與其背後的資料合成層。
> 不變的硬約束：**單一 HTML、零外部請求、vanilla JS、雙擊即開、無 npm/node**。

---

## 一、現況診斷：為什麼現在的版面「抓不到重點」

現行版面（由上而下）：標題 → 昨夜美股新聞全文（極長）→ 基金分頁 tabs → 單檔基金卡 → 合規 footer。

| # | 問題 | 對業務的實際傷害 |
|---|------|------------------|
| P1 | **新聞全文霸佔首屏**。v1 速寫包動輒數千字，是「閱讀型」內容卻放在「速覽位」 | 每天開頁第一眼是牆一般的文字，找基金資訊要滾過整篇新聞 |
| P2 | **基金採 tabs、一次只看一檔** | 業務最常見的起手問題是「今天哪檔能講？」需要 11 檔橫向比較，現在得點 11 次 tab 用腦子記 |
| P3 | **沒有「今日重點」層** | NAV 誰漲誰跌、誰 YTD 領先、昨夜新聞跟哪檔有關——全靠人腦自己拼 |
| P4 | **新聞與基金是兩座孤島** | 昨夜 Meta 大漲 9%、Micron 重挫 10%，明明就是我們基金的前十大持股，版面上卻零連結。這是對業務最值錢、目前完全缺席的資訊 |
| P5 | **資訊密度均勻、無視覺層級** | 經理人、風險等級、管理費與 NAV、報酬同等呈現；掃視時眼睛沒有落點 |
| P6 | **缺業務工具** | 沒有可複製的介紹文字、沒有列印／LINE 轉發友善格式；業務得自己抄 |
| P7 | **漲跌配色為美式（綠漲紅跌）** | 台灣金融慣例是**紅漲綠跌**，內部業務日常看台股行情軟體，反向配色會造成瞬間誤讀 |

## 二、設計原則

1. **3 秒／30 秒／3 分鐘三層架構**：glance（今日重點帶）→ scan（總覽表＋新聞連動）→ read（新聞全文＋基金詳情）。頁面由上而下就是這個順序。
2. **Insight-first**：先給結論（誰漲、誰跌、跟我們哪檔基金有關），原始資料退居下層供查證。
3. **每個區塊回答一個業務真實會被問的問題**：
   - 「今天市場怎麼了？」→ 今日重點帶
   - 「你們哪檔基金表現好？」→ 基金總覽表
   - 「昨晚那則新聞跟你們基金有關嗎？」→ 新聞×持股連動
   - 「這檔基金到底買什麼？」→ 基金詳情
4. **合規不退讓**：所有給業務的「可講素材」都是中性事實敘述，沿用 `gen_usnews.py --check` 的禁用詞掃描，合規燈全程可見（sticky bar 常駐）。

### ① 今日重點（新區塊）
- **三大指數卡**：從 v2 精簡版「指數速覽」段以 regex 萃取 Nasdaq／SOX／S&P500 收盤與漲跌幅（`usnews.py` 新增結構化萃取；萃取失敗則整卡隱藏、不擋版面）。
- **今日最強／最弱**：以各基金 `nav_change_pct` 排序取前一後一（同日 NAV 缺漏者剔除）。
- **連動計數**：「昨夜 N 則新聞連動 M 檔基金」，點擊捲動到區塊③。
- **配息提醒**（有才顯示）：`dist_date` 在 7 天內的基金列出。

### ② 基金總覽表（新區塊，主入口）
- 分「全球股票型」「全球平衡型」兩段（沿用 `group_label`）。
- 欄位：基金簡稱｜NAV（含日變動，紅漲綠跌）｜YTD｜1Y｜3Y｜規模（億）｜前十大集中度｜新聞連動數 🔗｜風險 RR。
- **同欄位色階**：各報酬欄位內以組內排名做淡色底（最高 2 檔淡紅底），掃一眼就知道誰領先。
- **可排序**：純 JS 點表頭排序（報酬字串 `"78.42%"` 需先在 Python 端解析為數值放進 `data-*`）。
- **點列 = 跳轉**該基金詳情錨點（tabs 廢除，改為「回總覽」浮動鈕）。
- 行動版（<720px）：表格改為每檔一張迷你卡（名稱＋NAV 日變動＋YTD＋1Y）。

### ③ 新聞 × 持股連動（新區塊，本次重設計的核心價值）
- **比對引擎**（新模組 `arm/fund_insights.py`）：
  1. 建立「公司識別表」：以 `config/holding_profiles.json` 的 35 檔 key（官方持股名）＋ `ticker` ＋人工維護的**別名表**（如 `META PLATFORMS INC` ↔「Meta」、`MICRON TECHNOLOGY` ↔「美光／Micron」）為索引。別名表放 `config/holding_aliases.json`，缺檔不崩。
  2. 掃描最新 usnews markdown 的新聞卡標題與摘要，命中即建立「新聞卡 ↔ 持股 ↔ 基金（權重）」三方連結。
  3. 輸出 `news_fund_links()`：`[{card_title, matched: [{company, ticker, funds: [(fund_name, weight)]}]}]`。
- **呈現**：每則有連動的新聞一張卡：一句話標題（取自卡片「一句話重點」行）＋受影響持股＋持有基金與權重＋**可複製的中性話術**。
- **話術產生規則（合規紅線）**：模板化、只陳述事實：「〈新聞一句話〉。本公司〈基金〉前十大持股含〈標的〉（權重 x%，持股基準〈as_of〉）。」不得出現推薦、預測字眼；產出後套 `compliance` 禁用詞掃描，命中則該話術改顯示 🔴 並隱藏複製鈕。
- 無任何命中時顯示「昨夜新聞與追蹤基金前十大持股無直接連動」——沒連動本身也是業務資訊。

### ④ 新聞全文（降級為收合）
- 預設收合，只露出「📅 日期＋Top3 標題三行＋合規燈」；點擊展開完整內容。
- 保留 v1／v2 切換與現有精緻排版（`.ndoc` 樣式全數沿用）。

### ⑤ 基金詳情（改良，不重寫）
- 保留現有卡片結構，全部展開改為**錨點直達**（`id="fund-{id}"`）。
- 報酬格新增「同組平均」對照列：股票型 8 檔／平衡型 3 檔各算術平均，該基金高於平均者標紅點。
- 持股表中**有新聞連動的標的整列淡黃底＋🔗**，點擊回捲到區塊③。
- 卡片右上加 `[📋 複製基金介紹]`：以 `navigator.clipboard` 複製「基金名／類型／NAV／多期報酬／前三大持股／月報連結」的純文字版（LINE 貼給通路直接可用），文末自動附「資料來源與免責」一行。
- 風險等級、管理費、經理人降為次要小字列；`strategy` 保留但收合至兩行、點擊展開。

### ⑥ 視覺系統調整
- **紅漲綠跌**：`--up` 改紅（#e5484d 系）、`--dn` 改綠（#3fb950 系），全站一致（總覽表、NAV 盒、Brief）。CSS 變數命名同時改為 `--gain`/`--loss` 避免語意混淆。
- 版心由 1080px 放寬至 1240px（總覽表 9 欄需要寬度）。
- 深色主題、卡片圓角、既有字階全部沿用；只調層級不換皮膚。
- 新增 `@media print`：只印「今日重點＋總覽表＋新聞連動」，白底黑字一頁 A4 ——**晨會速報**直接列印。

## 四、資料／程式層改動

| 檔案 | 動作 | 內容 |
|------|------|------|
| `arm/fund_insights.py` | **新增** | `overview_rows()`（含報酬字串→float 解析）、`movers()`、`group_averages()`、`news_fund_links()`、`upcoming_distributions()`。純函式、可單測、缺資料回空 |
| `config/holding_aliases.json` | **新增** | 官方持股名 → 新聞常見稱呼別名表（含中文名）。缺檔時只用 profiles 的 name/ticker 比對 |
| `arm/usnews.py` | 擴充 | `extract_indices(md)`（三大指數）、`extract_card_headlines(md)`（Top3 卡標題＋一句話重點） |
| `arm/fund_dashboard.py` | **重構** | 拆為區塊函式 `_topbar/_brief/_overview/_newslinks/_news_full/_fund_detail/_foot`，`render()` 只負責組裝；CSS/JS 相應擴充（排序、收合、複製、錨點高亮） |
| `tests/test_dashboard.py` | 擴充 | 區塊存在性、排序 data 屬性、收合預設狀態 |
| `tests/test_insights.py` | **新增** | 別名比對命中／不命中、報酬解析（含 `—`、負值）、同組平均、話術禁用詞掃描 |

**不動的部分**：`fetch_holdings.py`、`gen_usnews.py`、資料 schema、發布腳本（產出仍是單一 `index.html`）。

## 五、分階段實作

| 階段 | 內容 | 產值 | 預估 |
|------|------|------|------|
| **Phase 1 · 層級重排** | Sticky 頂欄＋今日重點帶＋基金總覽表＋新聞收合＋錨點詳情＋紅漲綠跌 | 解決 P1/P2/P3/P5/P7，版面邏輯即刻翻轉 | 1 天 |
| **Phase 2 · 連動引擎** | `fund_insights.news_fund_links()`＋別名表＋新聞×持股區塊＋詳情持股表連動高亮 | 解決 P4，業務核心價值上線 | 1 天 |
| **Phase 3 · 業務工具** | 話術模板＋複製鈕（含合規掃描）、複製基金介紹、`@media print` 晨會版、行動版卡片化 | 解決 P6，從「看的儀表板」變「用的工具」 | 0.5–1 天 |

每階段結尾跑 `python3 -m pytest tests/` 與 `gen_fund_dashboard.py` 實產驗收；Phase 之間可獨立上線。

## 六、需拍板的決策點

- **D1 紅漲綠跌**：規劃預設改為台灣慣例（紅漲綠跌）。若儀表板未來也給看慣美股配色的同仁，可加一鍵切換（localStorage 記憶）——預設仍紅漲。
- **D2 tabs 是否保留**：規劃為**廢除**，總覽表點列跳轉取代。若業務習慣既有 tabs，可在詳情區頂部保留一排「快速跳檔」錨點鏈（成本極低）。
- **D3 別名表維護責任**：新聞連動精度取決於 `holding_aliases.json`。建議先人工建 35 檔一次（一次性 30 分鐘），之後隨 `holding_profiles.json` 新增持股時同步維護。
- **D4 話術合規**：模板僅中性事實＋自動禁用詞掃描已設防線；是否需要法遵先審模板文字一次，由內部流程決定（建議：審一次模板，之後自動化）。
- **D5 台股版（todo.md D2）**：本規劃的區塊化重構（`_brief/_overview/...` 函式）天然支援 todo.md 規劃中的 `dashboard/tw.html` 獨立頁——同引擎換資料源即可，建議海外版重構先行。

## 七、成功指標（驗收標準）

1. 開頁**不捲動**即可看到：三大指數、最強最弱基金、新聞連動數、合規燈。
2. 「今天哪檔基金 YTD 最好？」——總覽表點一次表頭排序即得，≤ 5 秒。
3. 「昨晚 Meta 新聞跟我們哪檔有關？」——新聞連動區直接列出基金與權重，≤ 10 秒。
4. 業務可一鍵複製單檔基金介紹（含免責）貼進 LINE，零手抄。
5. 晨會列印一頁 A4 完整涵蓋當日重點。
6. 全部功能維持零外部請求、單一 HTML、雙擊即開；`pytest` 全綠。
