# 個股報告：買進建議旁邊按一下，排程當晚補上

> 2026-10-30 使用者：「個股報告不是應該在你給我買進建議的時候就要做了嗎？我覺得可以的流程是你給我買進策略建議，然後我可以按是否需要個股報告，
> 然後你在某一個排程的時候來看然後再補上」「幫我詳細規劃再逐步執行」。
> 前一份規劃：`docs/lab_equity_report_plan.md`（報告本身怎麼做）；這份只改「什麼時候做、誰決定要做」。

## 1. 結論（建議）

照使用者說的流程：選股頁每一筆買進、每一張個股卡都有「要個股報告」，按了排進佇列；**每天晚上一班排程**看佇列，有就做、沒有就安靜結束；
做好之後，卡片上的按鈕自動變成報告連結。另外保留一小段自動：**接下來 2 個交易日要買、還沒有報告的**，排程自己補——
買進建議出來的當晚就有報告，不用每一檔去按。

## 2. 現在怎麼做（10/29 起）

- 每週六 14:17 一班（Routine ⑦）：只做「下週一要買的」新飆股與美股強勢品質股，加上出了新財報的季更新，每週最多 4 家（`arm/lab/eqqueue.py`）。
  第一次會在 10/31 跑。（10/30 發現並修好：新飆股名單改格式之後，這班原本會一家台股都排不到，PR #411。）
- 不夠的地方：
  1. 長線、財報驚喜、臺灣50 提前卡位等其他策略的買進，不在名單上；
  2. 不是週一的買進（例 11/17 財報驚喜換股）等不到週六那班；
  3. 想看其他公司的報告，只能在對話裡打「個股報告 代號」。
- 成本：一份個股報告約 15～25 次搜尋、15～25 萬 token；同產業的產業報告 31 天內共用，新做一份約 10～15 萬。

## 3. 新流程

### 3.1 網頁上按「要個股報告」

- **個股卡最上面那一行**（台股個股卡、公司卡、美股個股卡；現在有報告才出現，`page.eqRepLine`）改成三種：
  - 有報告 → 「個股報告（10/30，減碼）」連結（不變）；
  - 已申請 → 「個股報告：已申請（10/30），當晚那班做」；
  - 都沒有 → 「要個股報告」按鈕。
- **選股頁「這週要做的事」**：每一檔旁邊一個小標記（報告／已申請／要報告），點了同上。
- 研究紀錄頁「個股報告」段多一小塊「申請中」。

### 3.2 按了之後怎麼送到排程

網站是靜態網頁、沒有伺服器，需要一個收件匣。

- **建議：GitHub 申請單**。按鈕打開本 repo 的「個股報告申請」表單（`.github/ISSUE_TEMPLATE/eq-report.yml`），市場與代號已經填好，按「Submit」送出；
  手機要登入 GitHub 一次。一支小 workflow（`eq_inbox.yml`＋`scripts/eq_inbox.py`）收到後：
  1. 代號格式要對、資料庫裡要有這家（台股：選股頁資料庫，月底市值 40 億以上；美股：個股報告資料包做得出來的那幾檔，見第 7 節）；
     誰能申請見第 7 節；
  2. 寫進 `data/eq_requests.json`（市場、代號、名稱、單號、申請時間），在單上回一句「已排進今晚那班」；查不到這家就回「沒有這家的資料」並關單；
  3. 報告進 main 之後，在單上回報告連結、關單（`workflow_run` 接在 `daily.yml` 後面，另每天一次兜底）。
  - 不用新的密鑰（只用 workflow 自帶的權限）。
  - 單上的文字一律當資料：只取市場與代號、用固定格式比對，不放進任何指令；排程只讀 `data/eq_requests.json`，不讀單上的文字。
- 另一種：一鍵送出，不用開 GitHub。要在 Vercel 放一把只能開單的 GitHub 金鑰、加通關密語擋陌生人，多一支伺服器程式要維護。先不建議；之後嫌麻煩再加。
- 按下去之後，同一支手機上馬上顯示「已送出」（瀏覽器記住）；網頁上的「已申請」要等下一次建頁（一天好幾次）。

### 3.3 排程：每天晚上一班

- Routine ⑦ 改成**每天台北 20:47**（取代每週六 14:17；還是 7 個排程，綁同一個排程視窗；做法＝建新的、刪舊的）。
- 順序：①申請的（照申請先後）→ ②接下來 2 個交易日要買、還沒有報告的（選股頁「這週要做的事」那份事件，台股＋美股主要策略）→ ③季更新（只在週六）。
  **每班最多 3 家**；排不到的留到隔天。需要的產業報告先做（31 天內有就共用）。
- 做過、90 天內、之後沒有新一季財報 → 不重做，直接回「已經有報告（M/D）」並關單。
- 沒事做 → 安靜結束、不推播。做好 → push 本會話分支 → `daily.yml` 併檔通道（main 的檢查要過）→ 建頁 → 推播一句（例「個股報告：臻鼎-KY 減碼（申請）、中砂 中立（11/2 要買）」）。
- 推播不寫目標價；評等不影響任何策略、交易計畫或選股名單（同現在）。

## 4. 成本估計

- 自動那段：新飆股 8 格、抱 60 天，平常每週約 1～2 檔新買進；美股強勢品質股每週 0～2 檔；其他策略每月幾檔 → 約每週 2～4 份（這週是 8 格第一次買滿，會比較多）。
- 申請：看按多少；每班上限 3 家。
- 沒事的晚上：只開機查一次佇列（幾萬 token）。

3. **排程**：`eqqueue` 讀申請與「接下來 2 個交易日要買」、每班上限、`scripts/eq_queue.py` 輸出；Routine ⑦ 改每天 20:47（CLAUDE.md 原文⑦與「排程搬家」那段、
