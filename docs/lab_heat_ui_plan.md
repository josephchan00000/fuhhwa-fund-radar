# 景氣溫度頁 呈現方式改版：總覽 → 面向 → 單項（規劃，2026-10-18）

## 0. 使用者需求

原話：「整體的呈現方式還是字太多了 如果說資訊太多你不用全部在一個畫面 你可以點進去再展開來看 因為資訊非常大你這樣會很難去解讀
你詳細規劃怎麼處理 可以參考專業儀表板設計的作品跟概念 再不影響到專業判讀的前提下深度詳盡分析跟我確認呈現方式再逐步執行」

讀者打開景氣頁要回答的問題，依序：

1. 各面向現在在哪一區？短線、中線、長線各看哪幾個？（5 秒）
2. 這週有什麼變了？（10 秒）
3. 某個面向是哪幾項在拉高或拉低？（30 秒）
4. 某一項：歷史位置、走勢、研究結論？（點開才看）
5. 研究怎麼做、完整數字？（另一個畫面）

範圍：台股景氣（x9m.html）與美股景氣（x9mu.html）。兩頁共用 `arm/lab/heatpage.py`，改一次兩頁一起換。
**只改呈現**：分數、0～100、研究的算法與規格（heatspec VER 7、heatspec_us VER 1）都不動，研究檔不用重跑。

## 2. 專業儀表板的做法，以及用在這裡的地方

| 來源 | 做法 | 用在這裡 |
|---|---|---|
| Stephen Few《Information Dashboard Design》 | 儀表板＝把最重要的資訊放在一個畫面，一眼看完 | 總覽一屏：短中長線、六面向熱度表、這週變化 |
| Few 的子彈圖（bullet graph） | 一條橫條同時表示數值、所在區間、比較值，取代儀表盤 | 每一項的 0～100 條：背景五區、從 50 往外的長度＝拉動、灰線＝上週 |
| Shneiderman「先總覽、再縮放篩選、細節要用時才給」 | 三步：overview → zoom/filter → details on demand | 三層：總覽 → 面向表 → 單項面板 |
| Nielsen Norman Group 漸進揭露 | 先放常用的，次要的點了才出現；超過兩層容易迷路；要看得出怎麼進下一層 | 最多兩層（單項面板、研究畫面）；每一列可點、每個「研究」行有連結 |
| Nielsen Norman Group 讀者掃描研究 | 79% 的受測者掃讀新頁面、16% 逐字讀 | 句子拆成表頭＋數字；列內不寫句子 |
| Tufte 迷你走勢線（sparkline） | 字大小的圖，放在數字旁邊 | 每一項近 52 週的 0～100 小走勢 |
| CNN 恐懼貪婪指數 | 一個總指數＋7 個構成指標，各自有讀數，點進去看走勢 | 面向分數＋各項 0～100，點一項看走勢與研究 |

## 3. 新結構

### 3.1 總覽（第一屏）

1. 一行說明：每一項和自己的過去比，換成 0～100；面向分數＝項目平均。點任何一項看細節。
2. **短中長線三列**：每列列出相關面向的分數與區（和現在的 HORIZON_NOTE 同一套分組；**不算短中長線總分**，2026-10-17 的決定不變）。
3. **熱度表**（現在的 52 週色帶保留，所有面向對齊同一條時間軸）：面向｜近 52 週｜分數＋區｜週變化｜連續幾週｜歷史位置｜上次這麼熱／冷。
   標籤放表頭一次，列內只放數字；手機把後三欄併成一行小字。
4. **這週變化**（和 5 個交易日前比；全部用現有數字算，不是新研究）：面向換區、項目進入／離開過熱過冷、
   變動最大（0～100 變動 ≥ 20 的前 3 項）、歷史極端（有資料以來最高／最低、3 年以上新高／新低）。點名稱打開單項面板。

### 3.2 對照台股

圖與操作不變。只選一條線時圖下的「單項分析」四塊、選多條時的「交互分析」：每塊先寫一行結論，數字表收起。

### 3.3 面向（每個面向一段）

1. 標題列：名稱、短中長線、看多久、分數、區、週變化（上週分數）。「熱＝…」放 ⓘ。
2. 五區量尺（不變）。
3. 兩行：「過去在這一區時，之後 120／250 日平均與上漲比例；所有日子」、「過去關係：判定字眼」。
4. 「各區明細」收起（就是現在驗證段的「面向分數各區」表，同一個函式）。
5. 泡沫面向另加一行：分數 ≥ 80 之後一年、兩年內大跌的比例與所有月份比；參考讀數收起。
6. **項目表，每項一列**：項目｜現值與日期｜近 52 週小走勢｜0～100 條｜分數｜拉動（佔比）｜本週｜位置與邊際變化標籤。
   - 0～100 條：背景是五區、黑線是現在、灰線是上週、色條從 50 畫到現在＝拉動（長度和拉動成正比）。
   - 位置標籤只在極端時出現（「有資料以來最高」「42 年新高」）；邊際變化標籤（「▲ 加速 3 個月」）只在核心 13 項。
   - 手機每項三行：名稱＋分數／條／現值、拉動與標籤。
   - 點一列打開單項面板。

### 3.4 單項面板（電腦右側 440 px、手機全螢幕；和籌碼雷達的個股卡同一種）

1. 現值與日期、0～100 與區（本週變化）、拉動（佔面向幾 %）。
2. 歷史位置：近 3 年、近 10 年、有資料以來三條百分位條（「高於 99%」「低於 100%」）；「有資料以來最高（資料從 1985 年起）」；近 10 年最高、最低與日期。
3. 走勢：0～100（上）與加權指數（下），近 3 年每週（用頁面本來就在下載的 x9mh.json）；按鈕「在上方對照圖看（可加其他線一起比）」。
4. 邊際變化一句（核心 13 項）。
5. 研究（只當參考）：熱了之後、跟著走還是領先、Granger 兩個方向、進入過熱／過冷之後、加速之後；連結「完整數字在研究與驗證」。
6. 定義。
7. ‹ › 換同一面向的上一項、下一項；× 或 Esc 關閉；手機返回鍵關閉。

### 3.5 邊際變化

一行加總（「13 項裡 10 項在加速：景氣動能 5/7、通膨利率 4/4、籌碼 1/2」）＋研究結論一句；13 項明細收起。每一項的加速標籤已經在面向表。

### 3.6 關鍵價位

均線表、支撐壓力一行、近 60 日事件；16 種事件之後的表現搬到研究畫面，這裡留一行結論。

### 3.7 研究與驗證（同一頁的另一個畫面）

頂欄右邊「研究與驗證 →」。原封搬過來：分數怎麼來、各版分析說明、各項和台股的關係、多層回歸（第六版）、各面向驗證、泡沫事件、
技術事件之後的表現、資料來源與筆數。主畫面每個「研究」行和單項面板都有連結直達，「← 回到總覽」回來。

## 5. 文字規則（寫進測試）

1. 主畫面不寫段落；一句 40 字以內；說明放 ⓘ 或單項面板。
2. 每一項一列；列內只有名稱、數字、標籤。
3. 標籤放在表頭一次，不在每列重複。
4. 判定字眼不變：熱了之後較弱／較強、看不出穩定關係、樣本不足。
5. 顏色一定配文字（區名、▲▼、標籤）。
6. 禁用詞照舊。

## 6. 不影響專業判讀的做法

1. **不刪任何數字**：研究內容用同一個函式產生、整段搬到研究畫面；測試直接比對產生的 HTML 字串在新頁面裡一模一樣。
2. 每一項都有一列＋一個單項面板（測試逐項檢查 51 項，美股各指數同）。
3. 兩層以內：主畫面 → 單項面板或「細節」→ 研究畫面。
4. 手機 390 px 不橫捲；面板全螢幕；返回鍵關閉。
5. 單項面板的內容在建頁時就產生（`<template>`），不是瀏覽器另外算，測試讀得到。

## 8. 要使用者決定的事

1. 範圍：景氣兩頁一起（建議；共用程式）／連個股頁（x9.html）一起規劃。
2. 細節怎麼打開：右側面板、手機全螢幕（建議）／原地展開／另開一頁。
3. 研究與驗證放哪：同一頁另一個畫面（建議）／頁尾全部收起／各面向底下收起。
4. 第一屏：短中長線＋熱度表＋這週變化（建議）／只留熱度表（右邊長句改短）／六張大字卡。
