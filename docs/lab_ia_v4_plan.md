# 籌碼雷達 v4：整頁以「策略選股」為主軸重排＋後台自我驗證（規劃，2026-10-15）

## 0. 使用者需求

原話：「整個的編排邏輯都很亂，每個分頁想表達什麼沒辦法一眼看出，然後希望瀏覽者的目的也看不出來。這個的邏輯應該是要幫助瀏覽者
知道各個不同的策略找出了哪些有機會的股票、建議的策略、還有隱含的獲利如何。你可以另外在後台有一個自我驗證策略，然後自己安排
每日更新跟我說。詳細規劃後跟我確認再執行。」

和 v3（同日稍早）的差別：v3 只改了策略、訊號兩頁；這次是整頁的架構，從「這個網頁要讓人做什麼」重新排。

## 1. 網頁目的（放在頁首，一句話）

> 用固定規則的選股策略，列出每條策略這一期選到的股票、哪天買賣，以及同樣做法過去實際賺多少。

讀者打開網頁要回答的三件事，依序：

1. **各策略找到哪些股票**（什麼時候買、抱多久、什麼時候賣）
2. **推薦哪些策略**（推薦順序與理由）
3. **隱含獲利**（同一規則過去照做的實際報酬，和同期大盤比）

其他東西（ETF 與投信籌碼、訊號、指數換股）是策略的原料，放在後面的分頁；驗證與研究放後台。

## 3. 新架構

頁首：標題＋第 1 節那句目的＋資料日。分頁五個，每頁最上面一句話說這頁回答什麼：

| 分頁 | 這頁回答什麼 | 內容（依序） | 從哪裡來 |
|---|---|---|---|
| **機會**（首頁） | 各策略這一期選到哪些股票，哪天買賣，過去照做賺多少 | 摘要列 → 時間表 → 每條推薦策略一張卡（依推薦順序） → 避開清單 | 策略頁行事曆、今日頁「接下來要做的事」、避開 |
| **策略** | 每條策略怎麼選股、推薦程度、過去照做賺多少 | 策略比較表（推薦順序、隱含獲利、年化對大盤） → 各策略說明卡（做法、逐年報酬、1 元變多少、風險） → 部位怎麼算 | 策略頁一覽、說明卡、部位 |
| **個股** | 查任何一檔：有沒有被策略選到、籌碼、技術面 | 個股表（新增「只看策略選到的」篩選與策略標記） → 個股卡（最上面新增「策略」段） | 個股頁 |
| **籌碼** | 主動 ETF、投信最近在買賣什麼、出現哪些訊號（原料，不是買進清單） | 重點 → 買最多／賣最多 → 新建倉 → 投信動向 → 今日訊號 → 風險提醒 | 今日頁、投信頁、訊號頁名單 |
| **指數** | 被動 ETF 什麼時候換股、預估換哪些股票 | 時程 → 臺灣50 預測 → 高股息預估名單 → 被動 ETF 換股動作 → 其他指數 | 指數頁的預測部分 |
| **後台**（頂欄小字，不在分頁列） | 策略自我驗證與研究 | 每日驗證摘要 → 前瞻紀錄 → 評級規則與總表 → 各策略評級依據 → 全部策略總表 → 訊號成績 → 指數換股研究 → 每日更新時程 | 驗證頁、訊號頁成績表、指數頁研究 |

內容都不刪，只搬位置；重複的（今日頁與策略頁兩份「接下來要做的事」）只留機會頁一份。

### 3.2 策略

比較表一列一條策略：推薦順序、做法、持有多久、每次平均／中位、賺錢比例、最差、同期大盤、年化與大盤年化。
下面每條策略一張說明卡（v3 的結論／怎麼做／過去成績／風險），卡底「後台驗證 →」。

### 3.3 個股

- 個股表加一個篩選鈕「策略選到的」，股名旁標策略小標籤（例：財報驚喜・持有中）。
- 個股卡最上面加「策略」段：被哪幾條策略選到、狀態（待買進／持有中）、買賣日期、該策略的隱含獲利。

### 3.4 籌碼、指數

原內容照搬，每頁最上面加一句：「這頁是原料資料，不是買進清單；要買什麼看『機會』」。
訊號只留今天名單與一句結論（照做輸大盤，只當觀察），成績表搬到後台。

## 4. 推薦順序與隱含獲利（定義寫死、由資料每天算）

- **推薦順序**＝現在評級總表的順序：A 在前；同級依證據強弱（有 2013～2021 事後驗證的在前，再依 t 值）。
  頁面不出現 t 值，改寫白話理由，三種：「N 年資料，事後驗證也贏」「N 年資料，事後驗證偏弱」「資料只有 N 個月／N 次」。
- **隱含獲利**＝同一規則過去照做的實際報酬（扣成本）：每次（或每檔）平均、中位、賺錢比例、最差一次；同期大盤；
  有長歷史的另給全部資金照做年化與同期大盤年化。都是歷史統計，頁面寫明不是預測。
- 評級（A／B／C）與部位上限照舊，不改任何門檻。

## 5. 後台自我驗證（每天自動）

### 5.1 每天自動做的事

每次重建頁面（CI 每天多班：清晨美股收盤後、06:35、盤後 15:40、晚間 ETF 持股與融資券）都會：

1. 重算每條策略的前瞻成績（規則起算日之後的交易）與評級（現在就有）。
2. **新增**：寫一筆當天的驗證紀錄 `data/lab/val_log.json`（以資料日為鍵，同一天後面的班次覆蓋；保留 250 天）：
   每條策略的評級、前瞻筆數與平均報酬（同期大盤）、持有中部位的平均報酬、待買進檔數；以及當天的事件。
   只在 CI 寫（`GITHUB_ACTIONS`），容器本機重建不寫，避免本機檔案混進 commit。

### 5.2 事件規則（事前寫定，觸發才記）

| 事件 | 條件 |
|---|---|
| 評級變動 | 和前一個資料日的評級不同 |
| 前瞻滿額 | 前瞻筆數第一次達到 A 級門檻（短線 10 筆、事件型 2 次），附平均報酬與同期大盤 |
| 前瞻落後 | 前瞻筆數 ≥ 門檻一半，且平均輸同一批股票 |
| 持有中虧損超過歷史最差 | 持有中部位平均報酬低於該策略過去最差的一次 |
| 該出名單沒出 | 名單產生日已過，卻沒有產生名單 |
| 資料過期 | 資料日落後最新交易日 2 天以上 |

### 5.3 後台頁面

最上面是今天的驗證摘要（一句話＋事件），接著前瞻紀錄表（每條策略：起算日、已出場筆數、平均報酬、同期大盤、距 A 級門檻），
再來是現有的驗證與研究內容，最後是每日更新時程（哪一班更新哪些資料）。

### 5.4 怎麼跟你說（待確認）

推薦做法：每天 06:35 那班排程本來就會推播新聞摘要，多帶兩行：
「今天開盤要做的事」（行事曆上今天的買賣）與「策略驗證」（有事件才寫，沒事件不寫）。
不另開新排程；需要改那支排程的指示（CLAUDE.md 原文＋現有排程），改之前會先跟你確認。
